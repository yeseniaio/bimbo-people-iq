# Track 2 - Guia de Datos para AI/BI Dashboard

Catalogo de metricas, dimensiones y datasets sugeridos para armar tu dashboard AI/BI.
Para cada escenario tienes: KPIs, dimensiones para filtrar/agrupar y un **dataset**
(la query SQL que alimenta una pagina del dashboard). Todas las queries fueron validadas
contra el workspace.

**Catalogo:** `cat_poc_sandbox_peopleai` &nbsp; **Schema:** `hackaton_2026_people_ai`

- Referencia tecnica de columnas: [Catalogo de Tablas](../Track%203%20-%20Databricks%20App/01.%20Catalogo-Tablas.md)
- Escenarios en detalle: [Casos de Uso](../00.%20Casos-de-uso.md)
- Como construir el dashboard: [Guia para Crear tu AI/BI Dashboard](02.%20Guia-Crear-AIBI-Dashboard.md)

> **Nota SQL para dashboards:** en la interfaz de AI/BI (editor de dataset) puedes usar el
> nombre completo `cat_poc_sandbox_peopleai.hackaton_2026_people_ai.<tabla>`. Solo si
> despliegas el dashboard por CLI (JSON serializado) las queries deben usar el nombre de
> tabla "pelado" (`FROM tbl_yl_sayit`) y el catalogo/schema se pasan aparte.

> ⚠️ **DATOS SIMULADOS:** todo el dato es **ficticio** (no real). `clean_name`, `email_empresa`
> y `salario_mensual` son nombres/correos/salarios **simulados**, no de personas reales. Aun asi,
> en el dashboard muestra siempre metricas **agregadas** (promedios, conteos, %), no filas
> individuales.

## Consejos de diseno (AI/BI)

- **Un dataset ancho por dominio** alimenta varios widgets y habilita el cross-filter (clic
  en una barra filtra el resto de la pagina).
- **KPI arriba, tendencia en medio, detalle abajo.** Cuenta una historia: "aqui pasa algo".
- **Cardinalidad:** colores/series con 3-8 valores; alta cardinalidad va en tabla.
- **Filtro de fecha global** cuando hay columna temporal (`fecha_de_cierre`, `year`).
- **Formato:** % como 0-1 con formato porcentaje, o 0-100 con formato numero.

## Escenario 2: Experiencia del Colaborador (mejor soportado)

**KPIs:** % Favorable global (Likert), % Favorable por indice (liderazgo/cultura/retencion),
variacion 2025 vs 2024, tasa de rotacion, rotacion voluntaria %.

**Dimensiones:** `dimention`, `year`, `grupo_area_funcional`, `nivel`, `generacion`.

**Dataset A - Clima por dimension y anio:**
```sql
SELECT year,
       dimention,
       ROUND(100.0 * SUM(CASE WHEN favorability='Favorable' THEN 1 END) / COUNT(*), 1) AS pct_favorable,
       COUNT(*) AS respuestas
FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_yl_sayit
WHERE scale = 'Likert' AND dimention <> ''
GROUP BY year, dimention
ORDER BY year, pct_favorable;
```

**Dataset B - Rotacion mensual por tipo:**
```sql
SELECT DATE_TRUNC('MONTH', fecha_de_baja) AS mes,
       tipo_de_baja,
       COUNT(*) AS bajas
FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_mth_datalake_personas
WHERE fecha_de_baja IS NOT NULL
GROUP BY 1, 2
ORDER BY 1;
```

> Caveat: en `tbl_yl_sayit` filtra siempre `scale='Likert'` (preguntas de escala). Cubre 1,072
> personas (subconjunto, 76,520 filas). No hay dimension de pais (ver Pendientes del README).

## Escenario 4: Gestion de Talento

**KPIs:** % con evaluacion de talento (cobertura), # altos potenciales, # Ready Now,
horas de capacitacion promedio del pool de talento, percentil promedio de competencias clave.

**Dimensiones:** `grupo_area_funcional`, `nivel`, `2026_Potential_Map`, `2026_Readiness`.

**Dataset - Competencias (talent_grid) por area:** el `talent_grid` (389 personas) cruza con
personas por `id_colaborador`. Cada competencia trae `_percentil` (0-100). Usa `dim_talent_grid`
para el significado de cada columna.
```sql
WITH u AS (SELECT MAX(fecha_de_cierre) m FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_mth_datalake_personas)
SELECT p.grupo_area_funcional,
       COUNT(*) AS evaluados,
       ROUND(AVG(g.strategic_mindset_percentil),0) AS strategic_mindset,
       ROUND(AVG(g.drives_results_percentil),0)    AS drives_results,
       ROUND(AVG(g.decision_quality_percentil),0)  AS decision_quality
FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.talent_grid g
JOIN cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_mth_datalake_personas p
  ON g.id_colaborador = p.id_colaborador, u
WHERE p.fecha_de_cierre = u.m
GROUP BY 1 ORDER BY evaluados DESC;
```

**Dataset - 9-box (potencial x desempenio) con dato:**
```sql
SELECT UPPER(TRIM(Potential_Evaluation)) AS potencial,
       UPPER(TRIM(Performance_Evaluation)) AS desempenio,
       COUNT(*) AS personas
FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_mth_datalake_personas
WHERE Performance_Evaluation NOT IN ('Without Data','')
  AND Potential_Evaluation  NOT IN ('Without Data','')
GROUP BY 1, 2
ORDER BY personas DESC;
```

**Dataset - Cobertura de evaluacion por area:**
```sql
WITH u AS (SELECT MAX(fecha_de_cierre) m FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_mth_datalake_personas)
SELECT grupo_area_funcional,
       COUNT(*) AS headcount,
       ROUND(100.0 * SUM(CASE WHEN Performance_Evaluation NOT IN ('Without Data','') THEN 1 END)/COUNT(*),1) AS pct_evaluado
FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_mth_datalake_personas, u
WHERE fecha_de_cierre = u.m AND active = 1
GROUP BY 1 ORDER BY headcount DESC;
```

> Caveat: normaliza etiquetas (UPPER/TRIM); la mayoria esta en `Without Data`.

## Escenario 5: Sucesion Basada en Datos

**KPIs:** # candidatos Ready Now, # posiciones clave, cobertura de sucesion,
antiguedad promedio del pipeline.

**Dimensiones:** `2026_Readiness`, `2026_Potential_Map`, `Key_Position`, `grupo_area_funcional`.

**Dataset A - Pipeline de sucesion:**
```sql
SELECT UPPER(TRIM(`2026_Readiness`)) AS readiness,
       `2026_Potential_Map` AS potencial,
       COUNT(*) AS personas
FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_wkly_talento
WHERE `2026_Readiness` NOT IN ('Without Data','')
GROUP BY 1, 2
ORDER BY personas DESC;
```

**Dataset B - Perfiles objetivo de roles criticos** (`perfiles_puesto_sucesion`): tabla de
referencia con lo que exige cada rol clave (capacidades, KPIs, requisitos). Sirve como **pagina
de detalle / catalogo** que el usuario consulta al analizar un candidato, o como fuente para un
panel "Ask" que responda "que exige el rol X".
```sql
SELECT puesto, categoria_perfil, area_funcional, nivel_alcance,
       objetivo_del_puesto, capacidades_criticas, req_must_have
FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.perfiles_puesto_sucesion
ORDER BY perfil_id;
```

> Caveat: `perfiles_puesto_sucesion` es el **perfil objetivo** (16 roles) — la version
> estructurada de la "Carpeta Azul". No cruza por llave dura a personas;
> el match candidato↔perfil se hace por `area_funcional` y por `capacidades_criticas` ≈
> `talent_grid`, o con Genie. Enriquece el ranking con `talent_grid` (competencias, learning
> agility) via `id_colaborador`. `Key_Position`/`SUCCESS_PROFILE_MATCH` en talento siguen casi vacios.

## Escenario 3: Compensacion (bandas internas + mercado)

**KPIs:** compa-ratio por categoria/nivel, % dentro de banda (min-max), dispersion por
categoria, brecha vs mercado, # categorias.

**Dimensiones:** `nivel`, `nombre_categoria`, `nivel_gb`, `grupo_area_funcional`.

**Dataset A - Compa-ratio y % dentro de banda:** `tabulador_cedulas_salariales` (bandas
internas) cruza con personas por `nombre_categoria` (match perfecto 51/51). Habilita medir
equidad vs la banda min/medio/max.
```sql
WITH u AS (SELECT MAX(fecha_de_cierre) m FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_mth_datalake_personas)
SELECT t.nivel_gb,
       COUNT(*) AS empleados,
       ROUND(AVG(p.salario_mensual)/AVG(t.valor_medio),2) AS compa_ratio,
       ROUND(100.0*SUM(CASE WHEN p.salario_mensual BETWEEN t.minimo AND t.maximo THEN 1 END)/COUNT(*),1) AS pct_dentro_banda
FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_mth_datalake_personas p
JOIN cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tabulador_cedulas_salariales t
  ON p.nombre_categoria = t.nombre_categoria, u
WHERE p.fecha_de_cierre = u.m AND p.active = 1 AND p.salario_mensual > 0
GROUP BY t.nivel_gb ORDER BY compa_ratio DESC;
```

**Dataset B - Referencia de mercado por nivel de carrera:** `datos_de_mercado_sueldos`
(benchmark tipo Mercer) da el sueldo de mercado por nivel de carrera (P1-P4 / M1-M3). Es una
**pagina de referencia**: ojo, NO se une directo a personas (personas no trae codigo de puesto).
```sql
SELECT `Nivel de carrera`,
       ROUND(AVG(`Sueldo Base (12 Meses) Promedio_OP`),0) AS sueldo_base_mercado,
       ROUND(AVG(`Compensación en Efectivo Total (Target) Promedio_OP`),0) AS comp_efectivo_total,
       COUNT(*) AS puestos
FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.datos_de_mercado_sueldos
GROUP BY `Nivel de carrera`
ORDER BY sueldo_base_mercado DESC;
```

> Caveat: categoria/plan/sitio estan hasheados (comparables, no legibles). El dato de mercado
> y `catalogo_puestos` se cruzan entre si por codigo, pero **no con personas** (referencia).
> Agrega el salario: nunca lo muestres por persona.

## Escenario 1: Biblioteca Virtual / Ask HR

Para AI/BI, este escenario se aborda como un **dashboard de conocimiento** (headcount,
capacitacion, clima) con **Genie/Q&A activado** para que el usuario pregunte en lenguaje
natural sobre lo que ve. Ver como enlazar Genie en la [guia de creacion](02.%20Guia-Crear-AIBI-Dashboard.md).

**Dataset - Capacitacion por academia (proveedor):**
```sql
SELECT provider,
       COUNT(*) AS eventos,
       ROUND(SUM(horas_de_capacitacion),0) AS horas_total,
       COUNT(DISTINCT id_usuario_sin_prefijos) AS personas
FROM cat_poc_sandbox_peopleai.hackaton_2026_people_ai.tbl_wkly_capacitacion
WHERE estado_de_la_capacitacion IN ('Approved','Completed')
GROUP BY provider
ORDER BY horas_total DESC;
```

> Caveat: el RAG sobre documentos institucionales es pendiente (no hay documentos en el
> volumen). Ver README y `Docs-Ejemplo (MUESTRAS)/`.
